# Deploy (Netlify Free + Neon Postgres)

Production runs on Netlify's free plan with a Neon free Postgres database. No card is needed for either.

- **Pages, loaders, actions, webhooks** run in a Netlify Function generated by `@netlify/vite-plugin-react-router` (Node 22, region `us-east-2`, next to Neon in Ohio).
- **Background jobs** use the Postgres `Job` table as the queue. Because serverless functions freeze between requests, there is no in-process loop in production (`DISABLE_EMBEDDED_WORKER=1`):
  - `netlify/functions/jobs-background.mts` is a background function that runs for up to 15 minutes. It puts stuck `RUNNING` jobs back in the queue, schedules the 15-minute `reconcile_all`, then drains due jobs and exits when the queue is empty.
  - `netlify/functions/jobs-tick.mts` is a scheduled function that runs every 5 minutes and wakes the background function. Scheduled functions only run on the production deploy.
  - `enqueue()` also wakes the background function as soon as new work is queued, debounced to once every 20 s per instance, so webhooks are processed within seconds.
  - Both functions require the `x-jobs-secret` header to match `JOBS_SECRET`. Jobs are claimed with a conditional update, so overlapping runners are safe.
- **Webhooks** check the HMAC, record the webhook id for dedupe, enqueue a job and return 200 at once.

## Environment variables (Netlify site settings)

| Key | Value |
| --- | --- |
| `DATABASE_URL` | Neon **pooled** URL (`-pooler` host) plus `?sslmode=require&pgbouncer=true&connection_limit=1&connect_timeout=15` |
| `DIRECT_URL` | Neon **direct** URL (no `-pooler`) plus `?sslmode=require&connect_timeout=15`. Used by `prisma migrate deploy` |
| `NODE_ENV` | `production` (turns off test charges) |
| `BILLING_MODE` | `manual_raw` |
| `SHOPIFY_APP_HANDLE` | `profit-dashboard-214` |
| `SHOPIFY_API_KEY` / `SHOPIFY_API_SECRET` | From `shopify app env show` |
| `SCOPES` | `read_orders,read_products,read_inventory` |
| `SHOPIFY_APP_URL` | `https://penni-app.netlify.app` (no trailing slash) |
| `DISABLE_EMBEDDED_WORKER` | `1` |
| `JOBS_SECRET` | Random string shared by the two job functions |

## Deploying

The site is not git-linked. Deploy from a machine that has the repo and a Netlify token:

```sh
NETLIFY_AUTH_TOKEN=... netlify deploy --build --site <site-id>           # draft deploy (free)
NETLIFY_AUTH_TOKEN=... netlify deploy --build --prod --site <site-id>    # production
```

The build (`netlify.toml`) runs `prisma generate`, then `prisma migrate deploy` against Neon, then `npm run build`. On the free plan each **production** deploy costs 15 of the 300 monthly credits, so test on draft deploys first.

Then point Shopify at the URL. `shopify.app.toml` already has `application_url` and `redirect_urls` set to the Netlify URL. Run `shopify app deploy` to release the config.

## Checks

- `https://penni-app.netlify.app/health` returns `ok`. Use it for uptime monitoring.
- `https://penni-app.netlify.app/privacy` renders the privacy policy.
- Unsigned POSTs to `/webhooks/*` return 400 or 401.

## Local dev

`shopify app dev` is unchanged. `DISABLE_EMBEDDED_WORKER` is unset locally, so the dev server runs the job loop in-process (`app/entry.server.tsx`). Local `.env` needs both `DATABASE_URL` and `DIRECT_URL`, and they can be the same local URL.

`Dockerfile` and `npm run worker` still work on any host that keeps a container running. In that case, leave `DISABLE_EMBEDDED_WORKER` unset, or run `node build/worker.js` as a separate process.
